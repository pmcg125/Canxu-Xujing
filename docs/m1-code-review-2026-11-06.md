## 3. 渲染和异常路径的约定

- 用户消息先保存，再完成 `message_sent`，之后才允许 `user_message_rendered`。实际渲染可早于事件结束，但证据只入队，不提前广播。
- 成功回复保存后，先通知 `message_received`，再允许真实渲染对应的 `character_message_rendered` 和后续 `message_updated`。已挂载且及时完成的消息按此顺序进入 `generation_ended`。
- 离屏消息或尚未完成的 HTML 最多等待 1.5 秒开始渲染，不阻塞整个生成流程。此时 `generation_ended` 可先结束生成；渲染事件和其后的更新会等到消息实际挂载后再发出。这是为满足真实渲染证据而明确保留的时序差异，需要测试 Agent 单独记录。
- 渲染已就绪但事件处理超过 30 秒时，取消该通知任务并记录超时，避免后续更新无限延迟。停止会取消对应渲染任务；JS 已开始执行的任意异步副作用仍需脚本配合停止，不能声称宿主能撤销它们。
- 已删除消息不使用旧索引兜底，其他会话的渲染不会写入当前会话；同文本的重生成按候选区分。
- 世界书既有默认值仍保留：默认扫描深度 4、预算 25% / 2048、递归轮数 8。显式递归 0 允许更多轮次，但有安全边界并输出诊断；不宣称与原版真正无界执行等价。
