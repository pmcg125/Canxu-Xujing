# 下一阶段开发目标：复杂角色卡运行正确性与长期使用稳定性

日期：2026-11-06。项目：残叙·残念（Xujing）。对照版本：PiuPiu Android 2.7.9。

基线提交：`201662bbddfe7c31752ea0ff9de2f49f2cb46a76`。编写前工作区干净。

本文把本次讨论确定的建议整理为开发目标和验收要求。本次交付仅为文档，以下任务均为待实施，不表示代码已经完成或测试已经通过。后续 Agent 开始工作时，应先核对当前提交和源码，避免重复实现已补功能。

## 1. 总目标与实施顺序

让代表性复杂角色卡在导入、聊天、交互、重生成、编辑、切换候选、切换会话、重启和回导后保持正确状态；世界书实际注入内容、脚本事件和变量变化应有可复查的依据。

| 阶段 | 目标 | 依赖与交付顺序 |
| --- | --- | --- |
| M1：下一批开发 | 世界书匹配更准确，消息生命周期事件更完整，高级参数可以操作 | 先明确原版行为契约，再实施世界书与事件；设置入口接同一份配置 |
| M2 | 扩展变量作用域并确定持久化、合并和导入导出规则 | 以 M1 的事件契约为基础，先定义状态归属，再接宿主与 JS |
| M3 | MVU / Zod 参与真实生成更新与写回 | 依赖 M2 状态契约；独立交付，避免与旧更新路径重复执行 |
| M4 | 大资料备份与后台生成稳定 | 可与 M2 / M3 分开推进；优先处理实际数据可靠性问题 |
| M5 | 改善记忆、回复建议与阅读体验 | 在相关链路稳定后逐项交付，不与 M1 混为一轮 |

验收样本与交接记录贯穿所有阶段。优先实施 M1，M2～M5 是后续完整路线，不是本轮的隐含实现范围。

## 3. M1：下一批开发任务

### M1-01：世界书角色过滤与生成模式过滤

目标：支持条目 `characterFilter` 和 `triggers`，让不适用于当前角色或生成模式的内容不会进入实际请求。

交付要求：

- 从 `PromptEngine.build` 将生成模式明确传到世界书激活入口，不能依赖界面上的临时状态推断。
- 对照原版确认名称、标签、排除条件、空过滤列表及多角色场景；处理导入字段的实际结构与别名。
- 明确 `normal / continue / regenerate / swipe` 等模式与原版触发条件的映射，不把不同模式统一当作普通发送。
- 依据参考实现确定过滤与常驻条目、sticky、递归、概率和预算的先后关系，保留未知字段。

验收证据：同一段历史和同一世界书，在包含/排除角色、标签匹配/不匹配、空条件、单聊/群聊及不同生成模式下，记录预期激活 ID、实际激活 ID 和模拟 API 收到的内容；被排除条目不得泄漏进其他注入位置。

### M1-02：扫描深度继承

目标：对齐条目显式配置 → 书级配置 → 全局默认的扫描深度继承，并支持有效的零值。

交付要求：

- 读取书级 `scan_depth` 等原版字段，保留每本书的配置来源。
- 区分字段缺失、`null`、非法值与显式 `0`；明确扫描扩展和 `maxDepth` 的继承方式。
- 最少激活条目引起的扩大扫描应遵守原版对显式值与继承值的区别。
- 深度 `0` 表示不扫描历史；角色资料等额外扫描源和递归文本是否参与，要分别按契约处理，不能直接等价为“条目永远不激活”。

验收证据：多本书分别使用不同默认值；覆盖条目覆盖书级、书级覆盖全局、缺失/非法回退、显式 `0`、扩大扫描。逐项核对窗口外文本没有意外触发，并回归已有延迟递归和预算零值用例。

### M1-03：互斥组关键词评分

目标：在原有 sticky、override 和权重处理的基础上，对齐 `useGroupScoring` 的筛选语义。

交付要求：

- 支持全局开关与条目级覆盖；依据参考实现计算主/副关键词命中得分。
- 按参考顺序执行 sticky、override、评分筛选、权重选择及其他激活条件；不能为了加入评分而改变已有优先级。
- 覆盖并列得分、多组成员、递归轮次及最终预算限制。

验收证据：固定时间与随机源，记录各候选的得分、淘汰原因、被选条目和最终注入；比较评分关闭、全局开启、条目覆盖、并列、sticky 与 override 的结果。固定随机源只用于可重复验证，不在本任务中擅自改变生产随机策略。

### M1-04：消息生命周期事件和参数

目标：脚本能正确观察发送、编辑、生成完成和渲染变化，事件回调中的数据与实际保存状态一致。

交付要求：

- 对照原版列出事件契约表，至少包含 `message_sent`、`message_edited`、`message_updated`、`message_received`、`character_message_rendered` 及现有生成/停止事件。
- 明确每个事件的参数、索引/稳定 ID 映射、可变参数、派发顺序和失败/取消分支。
- 补齐 `generation_started` 的剩余参数；核对 `generate_after_data` 的原版 `prompt` 与现有 `messages` 的兼容规则。两个字段同时存在、重新赋值或修改数组时要有确定的取值顺序，最终请求与提示词预览一致。
- 已有 `dryRun:false` 保持有效；用户发送或编辑导致的事件应基于相应状态提交成功后的快照。
- 渲染完成事件须有真实渲染依据，定义离屏、多个 HTML 片段及重新挂载的语义，不能仅因网络结束就伪造完成。
- 保持会话脚本和消息卡片的既定派发顺序、源环境排除、超时处理与销毁清理；新增事件不能重复触发变量更新或发起循环广播。

验收证据：记录普通发送、流式回复、续写、重生成、编辑、停止、失败、卡片回收和切换会话的事件轨迹及参数；核对各分支是否保存成功、触发次数、旧环境是否收到事件，以及事件修改是否进入真实 API 请求。

### M1-05：世界书高级设置与诊断入口

目标：用户和测试 Agent 能在应用内调整本批支持的参数，并确认其对下一次请求的影响。

交付要求：

- 在会话设置中增加高级折叠区，接入全局扫描深度、递归步数、预算比例、预算 cap 和组评分等已支持配置。
- 条目和书级值保持相应归属；界面说明继承优先级、零值含义，提供恢复继承/默认的操作。
- 使用现有配置数据源；保存时合并字段，不用基础模板整体覆盖导入配置。未编辑的值不得仅因打开设置页就被重写。
- 提示词详情能核对最终激活条目和必要的排除原因，不在普通聊天正文中暴露调试信息。

验收证据：修改、保存、离开、重新进入和重启后值正确；非法输入有明确反馈；下一次请求实际变化；未知扩展字段和未编辑的导入值保持原样。

### M1 完成条件

- M1-01～M1-05 均有实现位置、覆盖边界和对应证据；没有把待确认行为写成已完成。
- 每项先有原版参考结果或可复查的受控观测。仅源码推断的行为单独标注，不能计作运行验收通过。
- 核对实际 API 请求、事件轨迹、持久化状态与界面值，避免只验证 UI 显示。
- 保护现有预设正则、脚本隔离/按钮、HTML 分段、候选快照、摘要、导入导出与未知字段保留。
- 不出现跨会话错误写入、同一操作重复提交或保存失败仍派发成功事件；存在失败/阻塞项时保持未验收状态。

## 4. M2：变量作用域

目标：在现有 `chat / message / preset` 基础上，按参考实现接入 `global / character / extension / script / all` 等实际需要的作用域。

开发前输出作用域契约表：每种作用域的所有者、键、生命周期、同步读取来源、可写性、合并顺序、持久化位置及导入导出映射。`all` 等聚合视图的写行为必须核实，不能机械地给每个名称新增一个可写桶。

宿主持久数据是权威来源，JS 快照随提交成功后刷新；保持旧值校验、候选校验与冲突反馈。角色、脚本和扩展按稳定身份关联，处理删除、同名和导入 ID 重映射。

验收覆盖：跨会话和跨角色读取、脚本隔离、同名实体、应用重启、并发旧写入、候选切换、备份恢复与未知字段；核实预设变量在完整备份和设置导出中的保留约定。现有递归对象合并与数组整体替换必须保留。

## 5. M3：MVU / Zod 真实生成链

目标：模型输出进入可回调脚本的 MVU 阶段链，再按参考契约校验并保存最终状态。

- 明确初始化、更新开始、命令解析、Zod 校验、更新结束和写入前各阶段的事件、参数可变性、返回值与提交边界。
- 保持 `core` 无 Android 依赖；宿主负责调度 JS、超时、停止和事务提交。
- 为现有 Kotlin 更新解释器与 JS 路径定义唯一执行规则，同一回复只能更新一次。脚本关闭时采用什么路径要有明确约定。
- 保留 InitVar、历史重放、每个候选的状态快照、回溯和重启恢复行为。
- Zod 失败、脚本异常、停止和保存失败如何影响正文、变量与诊断，按原版结果明确记录，不能以兜底成功掩盖差异。

验收使用普通 MVU 卡、Zod 卡和 EJS 动态状态卡，记录每个阶段及最终变量；覆盖普通/流式、失败/停止、重生成、编辑、切候选、回溯和重启，并证明没有重复副作用。

后续世界书装饰器单独拆任务：先核实 `@@activate / @@dont_activate / @@only_preload / @@initial_variables / @@@`，再接 render/generate 阶段。有效控制行不得混入模型正文；不能把消息模板的 `@@` 处理当作世界书已支持。

## 6. M4：大数据与后台生成稳定性

| 子任务 | 交付要求 | 验收证据 |
| --- | --- | --- |
| 流式备份导出 | 避免同时把全部媒体和最终 ZIP 常驻内存；提供进度、取消与失败反馈 | 用大资料测量峰值内存；取消/失败不提示成功；成功包能重新导入并核对媒体与数据 |
| 数据库 v2 迁移与恢复 | 保持压缩、加密、分块及迁移事务；不修改用户原库做破坏性验证 | 使用可丢弃旧库样本覆盖大记录、多个分块和迁移失败；重开后数据一致、失败不留下半迁移状态 |
| 后台生成 | 明确前后台、屏幕关闭、用户停止、进程被终止的生命周期；按 Android 约束选择实现与通知 | 记录每条路径的请求、状态与通知；不重复回复，不长时间残留“生成中”；进程被终止后的结果或中断状态可解释 |
| 用量与诊断 | 提供数据库/媒体用量、可用空间与可导出的诊断信息 | 数值来源可复核；诊断不包含 API 凭据，聊天正文由用户决定是否附带 |

## 7. M5：日常聊天体验

按独立小批次实施：

1. 从正常回复提取 `<reply_suggestions>`，清除有效控制块、整理空白并随消息保存；保留现有手动建议入口，点选仍只填入输入框。
2. 记忆检索改为对最近多条消息分别查询，再按最大相似度聚合；保留阈值、topK、模型身份隔离与历史顺序。
3. 增加可查看、修改或移除相关记忆的页面，明确历史消息、摘要与索引各自的操作语义。
4. 支持正文、引用和括号颜色配置、实时预览、恢复默认，保持代码与链接保护以及卡片作者 HTML/CSS。
5. 回归并完善聊天搜索现有的 180ms 防抖与三次滚动定位，重点覆盖异步 HTML/图片超过现有等待窗口后继续撑高的情况；根据实际失败完善定位校正，避免重复实现已有机制。

每项验收包含保存/重启和受影响的真实操作流程；模型自由生成的质量不作为客户端确定行为的唯一依据。

## 8. 暂缓项与需要明确的行为差异

- 账号、VIP、邀请、社区、市场、Live2D 不进入本路线；TTS 和生图继续后置。无需为了对齐 PiuPiu 补入其服务端或固定凭据。
- 图片上传/视觉输入、BGM、内置或远端预设基座不进入 M1，后续按实际需求独立排期。
- 世界书默认参数与生产随机策略需要单独记录产品选择；M1 不顺带全局替换，导入行为和新建会话默认值应区分。
- 世界书时效状态内容哈希、额外扫描来源、`injectPrompts` / 注册宏、`generateRaw` / 按任务取消继续保留在后续缺口，不因 M1 完成而宣称完整兼容。
- 旧卡脚本键回退、JVM 与 JS 正则差异等问题，按代表性样本发现的实际失败安排修复，保留对应参考和回归记录。
