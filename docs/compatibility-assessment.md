# 角色扮演兼容性验收口径

目标是对 PiuPiu 酱 Android 2.7.9 的**客户端角色扮演行为**建立可复查的 90% 测试通过率。尚未建立足够完整的参考样本，因此当前不计算或宣称已达到某个百分比。

## 计量方式

建立版本固定、可重复执行的样本集。每个样本明确输入、来源、参考结果、残叙·残念结果和限制；以一个可独立观察的行为为一条测试。原版参考结果优先使用在隔离环境中运行的对应恢复函数；需要生命周期或端到端行为时使用原应用的受控观测。静态代码推断不能当作实际通过。

至少覆盖以下 8 类，每类不少于 5 条有效用例（至少 40 条），简单和复杂资料均需覆盖：

1. 角色卡、世界书、预设、正则、人设和聊天数据导入/导出与未知字段。
2. 提示词顺序、宏、群聊目标、生成前钩子和有效采样参数。
3. 世界书匹配、递归、预算、位置、状态及互斥组。
4. 输入/输出/显示正则、嵌套宏、JavaScript 替换语义。
5. TavernHelper 脚本加载、生命周期、事件、世界书和预设接口。
6. MVU、变量作用域、Zod、候选快照、重生成、回溯和重启。
7. EJS、HTML/CSS、消息交互、媒体引用和显示刷新。
8. 摘要与本地/远程记忆、查询窗口、检索注入、流式及停止。

同一个功能的导入成功、渲染成功、交互成功、状态持久化和回导成功分别记录。不能用“文件读入成功”计作复杂卡执行成功，也不能用一个固定 mock 回复评估模型智能。

达到目标的最低条件：样本集至少 90% 的有效用例通过；每类至少 80% 通过；数据损坏、跨会话串数据、错误提交状态等关键问题为零。记录排除项与已知差异。这个百分比仅代表该样本集和测试环境，不能证明全部第三方卡片或未来版本的兼容率。

## 原则和排除范围

- 使用合成资料以及用户愿意用于验证的真实资料，覆盖实际脚本、世界书和预设结构；不将用户隐私或密钥写入报告。随机和时间固定，比较消息顺序、文本、激活项、事件和数据状态。
- 客户端使用本机模拟 API 测试请求/流式，嵌入模型分别验证本地与远程；不同服务商生成质量单独评估。
- 云端内部逻辑、账号/VIP/邀请/社区、Live2D 不计入；语音和生图按既定需求后置。模型权重不随应用分发。
- 保存每次样本和测试结果、应用构建哈希、原应用版本及失败原因。回归通过不等同于已达到全部类别的 90%。

## 当前状态

本工程已有导入合并、设置往返、自动摘要、部分宏正则、世界书脚本接口、预设读取/选择和会话隔离的定向检查。这些检查尚不能组成上述具有参考结果的完整样本集。
